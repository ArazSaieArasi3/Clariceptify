# Conceptual model

The authoritative conceptual registers are [concepts](../../model/concepts.yaml),
[domains](../../model/domains.yaml), [associations](../../model/relations.yaml),
[generalizations](../../model/generalizations.yaml) and
[constraints](../../model/constraints.yaml). Edit those controlled sources and
regenerate projections; do not maintain independent definitions in a Wiki page.

The model preserves process versus product; mental state versus explicit content
and expression; description versus referent; content versus representation;
type versus instance; and criterion versus evaluation activity and result.
These are selected modeling commitments, not a completed semantic adequacy study.

The [reference catalogue](../reference/README.md) contains every concept/domain,
formal project definition, OntoUML stereotype, declared UFO type and qualified
source support. [Relations](../reference/relations/README.md) preserve class-end
multiplicities and named associations; generalization points to its parent.
Textual constraints remain distinct from a complete executable constraint system.

Use [Visualization](Visualization.md) for reading the diagram, and
[Requirements and CQs](Requirements-and-CQs.md) for candidate use witnesses.
