# Quality and evidence

The v0.1.0 publication record verifies the actual package, ten public assets,
checksums, 375 source/378 archive members and eleven extracted integrity layers.
All 233 protected scientific members match the accepted candidate. These are
bounded engineering observations, not proof of full ontological adequacy.

| VVEAA function | Current boundary | Next R2 work |
| --- | --- | --- |
| Verification | Actual schema, structure, trace, projection and package checks | Input-bound regression and defect tests after relevant changes |
| Validation | One selected synthetic clause; independent semantic review unperformed | Thirty CQ contracts, twenty domains, source/typing and actual human review |
| Evaluation | Recorded engineering observations with explicit populations | Governed evidence collection and qualitative/quantitative coverage by population |
| Assessment | Actual owner package-scope decision | Interpret R2 evidence/findings against explicit criteria; keep absent review visible |
| Assurance | Reproducible identity and release evidence are available | Maintain bounded claim, argument, evidence, assumptions, counterevidence and revision triggers |

The [profile](../../evaluation/vveaa-profile.yaml) specifies activities, methods,
evidence, denominators, owners and claim ceilings. The
[baseline report](../../evaluation/vveaa-report.yaml) preserves missing evidence.
Evaluation is an evidence process; assessment is a judgment; assurance is a maintained
case, not a final average score or certification. VVEAA is not a rigid linear sequence.

See [review states](../../evaluation/review-state.yaml),

[limitations](Limitations.md).
